  How the chunker works
  - Each chunk is an exact slice of the original text: text[start:end]. That's
    the only way to get both an overlap of exactly chunk_overlap characters and
    a join that reproduces the input exactly.
  - Each chunk starts chunk_overlap characters before the previous one ended.
  - Where it cuts: within the chunk-size window, it cuts at the last paragraph
    break. If there's none, it cuts at the last sentence end (., ! or ? followed
    by whitespace). If there's none of those either, it cuts hard at
    chunk_size.
  - Always moves forward: a cut has to land past the overlap zone, so every
    chunk adds new text and the loop can't stall.
  - Speed: the limit test caught a function at 11 lines. While splitting it I
    also fixed a quadratic scan: the boundary search now starts at each chunk's
    start instead of index 0. A 1.17M-character document splits into 2,999
